# 動的トレース・フィルタ VM

**優先度:** 低（[静的基盤](tracing.md) と [統合モニタ](thread-monitor.md) が正しく動いた後）。**中止ではなく、APP 予算に応じて構成を選択する機能。**

## 作るもの

- ファームウェアに予め存在する静的観測点を、PC の要求で有効／無効にする。v1 の操作は task ID、event type、model ID、frame 採択率などの**設定値更新**とし、実行中の任意アドレスへジャンプしない。
- ホストが設定の版／適用結果／対象ビルドを記録し、結果のトレースに設定 ID を含める。ホットパスの分岐は最小限にし、設定更新は producer と競合しない安全な境界で公開する。
- より複雑な条件だけをオプションの小さなフィルタ VM にする。対象イベントのコピーされた固定長フィールドのみ読める、無制限ループ・ポインタ間接参照・書込み・外部関数呼出し禁止。ロード時に型・命令数・参照範囲・分岐先・最悪実行時間を検証し、検証に失敗した設定は使用しない。

## 構成の切り分け

APP に余裕がない間はホストで取得済み記録をフィルタするだけにし、オンデバイスの VM は含めない。ただし記録量がリングを上書きして目的の窓を残せない場合は、VM を載せるより先に event mask／率制限を静的な小コードで導入する。VM／制御プロトコルの `.text`・`.bss` とリング保持時間を [容量表](../app-size-reduction.md) に列記し、空きと欠落改善が見合う場合に有効化する。

## 安全性と確認

NULL 関数ポインタチェックや MPU だけで安全性や一定のオーバーヘッドを保証しない。IRQ 中の最悪ケース、設定破損、並行更新、trace reentrancy、通信途絶後の復旧を試験し、無効状態のコストを実機で測る。フィルタによって落としたイベントはリングオーバーフローと別カウンタにする。[共通の実機ゲート](README.md#共通の検証ゲート)を通す。
