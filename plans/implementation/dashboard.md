# ホスト側ダッシュボード

**優先度:** 高。依存: [共通データ契約](tracing.md)。取得可能な情報から段階的に UI を広げる。

## 作るもの

- ボード側 UI は作らず、PC でトレースファイルを開くローカルダッシュボード。入力はバイナリダンプ（必要なら現行 ThreadMonitor のデコード結果を別 import）、ELF/map 由来の配置情報、実験メタデータ。ホストにデコーダ／解析器と UI を分離し、同じデータを再計算できるようにする。
- 概要画面は session ID・build ID・計測構成・欠落数・Pipe1/2／NPU の稼働と CSI エラーを表示。メインはフレーム ID で絞れる時系列（task Gantt、CPU、NPU、Pipe1/2、queue、error）と選択イベントの詳細・元レコードへの移動。
- 他にモデル別の p50／p95 と throughput、[スケジューリング](scheduling.md) の READY／WAIT 分布、[ボトルネック候補](bottlenecks.md) と根拠、[メモリ](memory.md) の APP／NOR／PSRAM 配置・slot 高水位を表示する。比較画面で通常版／計測版または NPU 無効／有効の差を見せる。

## 表示上の契約

- 実測区間・サンプルからの推測・欠落・未計測・時刻未同期・範囲外を見た目で区別し、数値には単位と測定点（capture→submit、submit→done 等）を付ける。上書き後の空白を補完した確定タイムラインにしない。
- デコーダ／解析を先にローカルのテスト可能なモジュールとして実装し、後から Web またはローカル UI を載せる。既存ダッシュボードの動作を前提にしない。初期表示はオフラインファイルに限定し、ライブ表示はストリーム品質が実測できてから有効化する。

## APP 依存

表示・集計・AI 用の依存はすべて PC に置き、APP サイズを使わない。軽量イベント構成でもある情報だけのビューを動かし、詳細モードがない場合は NPU epoch／task-switch のパネルを「未計測」とする。転送経路が SWD だけでも使えることを受け入れ条件とする。

## 完了条件

同一ファイルは同一表示・指標に復元され、未知形式と破損ファイルを安全に拒否する。欠落や warm reset を含む合成データに加え、Pipe1／Pipe2／NPU が進行する実機記録を使い、表示の根拠イベントまで辿れる。[共通の実機ゲート](README.md#共通の検証ゲート)を満たす記録を保存する。
