# sample-ai 動作確認チェックリスト

## 実行条件

- ボード: STM32N6570-DK
- 接続: ST-LINK、LCD、カメラ
- UART: 115200 bps、8N1
- 実行方法: RAMロード（この確認は外部フラッシュへの永続書込みではない）

## 最低限の合格条件

- [ ] **ビルド** — `cmake --build build --target sample-ai -j4` が成功する。
- [ ] **RAMロード** — STM32CubeProgrammerがロード完了と検証成功を報告し、指定したPCで実行を開始する。
- [ ] **起動・メモリー** — UARTに致命的な初期化エラーがなく、PSRAM/NORの初期化とモデルデータ読出しが成功する。
- [ ] **カメラ入力** — UARTで撮影フレームのsequenceが増加する。
- [ ] **LCD実表示** — LCD上に黒一色ではない画像が見え、カメラ映像の変化が画面にも反映される。
- [ ] **NPU推論** — UARTでモデル読込み後、推論sequenceが増加し、`npu done code=0` が出る。
- [ ] **継続動作** — 30秒以上、致命的エラーや停止なしにカメラ表示と推論が続く。

## 判定上の注意

- `lcd: frame presented` は、アプリケーションが表示バッファをLCDドライバーへ渡せたことを示すログであり、パネルに画像が見えた証拠ではない。LCD実表示は目視確認する。
- LCDが黒い、または映像が更新されない場合は不合格。UART上でフレームが提示されたログがあっても合格にしない。
- 非致命のカメラ/CSIエラーが出た場合は、件数と表示・推論への影響を記録する。フレームsequenceが進まない、または画面が止まる場合は不合格。
- RAMロード成功は永続書込み成功を意味しない。外部フラッシュへの書込みを行った場合は、別途その方法と検証結果を記録する。

## 最新の確認結果

- 2026-09-24、STM32N6570-DKへRAMロード。CubeProgrammerの書込み・照合・実行開始は成功。
- UARTでLCD初期化サイズ800×480、RGB565、LTDC有効を確認。
- 垂直ブランキング後のLTDCレイヤー有効化と表示バッファ `0x91200000` / `0x91300000` の切替を確認。
- カメラsequence増加とNPU `npu done code=0` を確認。撮影画像の明るさログはmean=132、peak=253。
- 追加のUART診断では、カメラの無フレーム判定が2秒で発生し、復旧の `BSP_CAMERA_Init()` を含む処理は約570msで完了。NPU timeoutは記録されず、復旧後はフレームsequenceが再開。
- 2026-09-25、Pipe2化後のperson構成をRAMロード。UARTで `pipe2 frame queued`、Pipe2イベント増加、`input ... pipe2=1`、`npu done code=0` を確認。15秒の採取中にCSIエラーは増加したが、Pipe1のフレームsequenceは継続し、カメラ`recovery`は発生しなかった。
- 同日、`AI_MODEL=segmentation` 構成もクロスビルド成功。
- **LCD実表示は未確認**。UARTとレジスター値はパネル上の表示を証明しないため、目視確認までこの項目は未合格。
