# sample-ai 再設計書

## 1. 目的

カメラ映像の表示を推論処理から分離する。

推論の初期化失敗、NPUの待ち時間、推論結果の欠落、推論タスクの遅延が発生しても、
カメラからLCDまでの表示経路は止めない。LCDには、カメラから取得した完全なフレームを
必ず別RAMへコピーしてから渡す。

`display RAM B`に描画する枠は、推論結果が届かない間は前回値を使う。ただし、
推論結果が3秒以上届かなければ古い枠を消す。推論結果が一度も届かない起動直後は
枠を表示しない。

## 2. 設計方針

### 2.1 表示を最優先にする

- カメラ表示タスクは推論APIを呼ばない。
- カメラ表示タスクは推論タスクからの応答を待たない。
- 推論用RAMが使用中なら、そのフレームの推論コピーを捨ててよい。
- 枠情報が受信できない場合は、最後に受信した枠を最大3秒保持する。
- 3秒以上新しい推論結果が届かなければ古い枠を消し、誤認識表示を残さない。
- 枠情報が一度も受信できない場合は、枠なしで表示する。

### 2.2 RAMの所有者を明確にする

- `capture RAM A` はカメラDMAが所有する。
- `display RAM B` はカメラ表示タスクが書き込み、LTDCが読み取る。
- `inference RAM C` は推論タスクが読み取る。
- カメラDMAが使用中のバッファにはCPUから書き込まない。
- LTDCが走査中の表示バッファにはCPUから書き込まない。
- 推論タスクが使用中のスナップショットは、カメラ表示タスクが再利用しない。

### 2.3 推論結果と映像フレームを同期させない

枠は映像フレームと完全に同じ世代である必要はない。表示タスクが受信した最新の
枠を次の表示フレームへ適用する。これにより、推論のフレームレートがカメラより
低くても表示は継続する。

## 4. バッファ設計

800×480 RGB565を1枚の基本サイズとする。

| 領域 | 枚数 | 用途 | 書き込み主体 | 読み取り主体 |
|---|---:|---|---|---|
| capture RAM A | 2 | DCMIPPカメラDMAの交互出力 | DCMIPP | camera_render_task |
| display RAM B | 2 | コピー画像＋枠、LCD走査用 | camera_render_task | LTDC |
| inference RAM C | 2 | 推論用の安定したスナップショット | camera_render_task | inference_task |

PSRAM上の固定配置は`stm32n6570-dk-npu-ram.ld`で予約する。capture/display/inferenceの
各スロットは1 MiB境界に配置し、raw dump、segmentation mask、inference scratchも
同じリンカスクリプトで重ならない領域として予約する。

```text
0x91000000  capture A0
0x91100000  capture A1
0x91200000  display B0
0x91300000  display B1
0x91400000  inference C0
0x91500000  inference C1
```

実際のアドレスと予約容量はリンカシンボルから`static_memory_layout`が取得し、各
ドライバや`MemoryAllocator`が個別に固定値を持たないようにする。`MemoryAllocator`は
この固定領域の中で、フレームサイズ・推論出力サイズ・アライメントなどの動的な
割り当てポリシーとバッファ所有権を管理する。設定したサイズがリンカ予約容量を
超える場合は初期化時に失敗させる。
