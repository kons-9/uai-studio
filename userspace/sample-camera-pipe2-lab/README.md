# sample-camera-pipe2-lab

## 実験の目的と画面の合格条件

`sample-camera-pipe2` を基準に、カメラ映像の段差や停止に関係する設計差を切り分けるための独立した実験用コピーです。

撮像確認のゴールは、IMX335のテストパターンを無効にした状態で、実景がLCDに連続表示されることです。dual表示では左右の領域に同じ実景が出て、格子などの真っすぐな縦横の境界が走査線ごとにずれず、少なくとも60秒間フリーズや再起動なくフレームカウンターが進むことを合格条件とします。

IMX335のカラーバーや一様パターンは、段差の位置を調べるための診断入力です。センサーが作る画像なので、カラーバーだけが見えている状態は実景の撮像確認を達成していません。段差の評価には、実景とは別に、縦横の直線を含む格子チャートまたはカラーバーを使います。

## pipe2からの主な設計差

| 項目 | `sample-camera-pipe2` | `sample-camera-pipe2-lab` |
| --- | --- | --- |
| センサー／CSI | Cube BSPの標準IMX335設定とBT_1600 | 標準設定を基準に、IMX335の891 Mbps設定とBT_900も選択可能 |
| パイプと画角 | Pipe1/2の各400×480。両方に同じ1620×1944領域を入力し、400×480へ縮小 | single/dualと、標準縮小・中央1600×1920の整数4倍縮小・中央800×480の非縮小を切り替え可能 |
| 初期化タスク | 1 KiBの初期タスク上で初期化 | 32 KiBの専用タスク上でカメラ初期化・表示を実行 |
| 実験用診断 | 通常の連続カメラ表示 | センサー内蔵テストパターン、起動設定とフレームカウンターのUART表示を追加。撮像バッファはSRAMを標準とし、PSRAMも選択可能 |

labの標準値はdual・標準センサー設定・SRAM・標準縮小・テストパターン無効です。比較時はpipe2と同じ条件から始め、変更する設計要素を一度に一つにします。

## 実機確認メモ

2026-09-25時点の実機確認では、`PIPE2_LAB_IMX335_PROFILE=mipi891`（BT900）で、UARTのフレームカウンターが進み続けていてもLCD映像に画乱れが発生した。したがって、BT900の判定はCSIエラーやフレームカウンターだけでは不十分で、LCDの実映像も合格条件に含める。

BT900の画乱れは、sample-aiのカメラ再起動問題とは別に記録する。比較時はまず `stock`（BT1600）を基準にし、同じpipeモード、バッファ配置、クロップ、テストパターン条件でBT900だけを切り替える。画乱れの切り分けでは、センサー内蔵テストパターンまたは格子チャートを使い、走査線単位のずれ・段差・色化けを確認する。
