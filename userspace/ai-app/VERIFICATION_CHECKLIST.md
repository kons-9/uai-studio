# ai-app 動作確認チェックリスト（未実施）

## 実行条件

- ボード: STM32N6570-DK
- 接続: ST-LINK、LCD、カメラ
- UART: 115200 bps、8N1
- 実行方法: RAMロード（この確認は外部フラッシュへの永続書込みではない）

## 最低限の合格条件

- [ ] **ビルド** — `make -C userspace/ai-app build` が成功する。
- [ ] **RAMロード** — STM32CubeProgrammerがロード完了と検証成功を報告し、指定したPCで実行を開始する。
- [ ] **起動・メモリー** — UARTに致命的な初期化エラーがなく、PSRAM/NORの初期化とモデルデータ読出しが成功する。
- [ ] **カメラ入力** — UARTで撮影フレームのsequenceが増加する。
- [ ] **LCD実表示** — LCD上に黒一色ではない画像が見え、カメラ映像の変化が画面にも反映される。
- [ ] **NPU推論** — UARTでモデル読込み後、推論sequenceが増加し、`npu done code=0` が出る。
- [ ] **継続動作** — 30秒以上、致命的エラーや停止なしにカメラ表示と推論が続く。

## AI露出制御（実機未確認）

- [ ] **UI切り替え** — 設定画面の`AI EXPOSURE`をOFFにするとUARTに`ui: ai exposure=off`が出て統計領域が全画面に戻る。ONでは新しい検出後だけ顔・人物・前景へ切り替わり、枠表示のON/OFFに影響されない。露出・ゲインの読み戻しとエラー表示を確認する。
- [ ] **収束と明滅** — 同じ照明条件の逆光・画面端の被写体で、AI露出ONと全画面AE（OFF）の対象領域の輝度偏差、収束フレーム数、統計領域の切り替え頻度を記録して比較する。被写体消失時の全画面復帰も確認する。統計領域だけで不足する場合に限り手動の露出・ゲイン制御を検討する。
- [ ] **AWB** — 統計領域の切り替え前後でホワイトバランスと画面全体の色を比較する。AWBへの悪影響がある場合は全画面維持または固定モードを検討する。
- [ ] **性能・安定性** — ON/OFFでISP/CSIエラー件数と両Pipeのフレーム進行を比較する。`thread-monitor`と`cpu-task-monitor`で推論FPSとCPU時間を計測し、露出制御による停止や性能低下がないか確認する。

## 判定上の注意

- `lcd: frame presented` は、アプリケーションが表示バッファをLCDドライバーへ渡せたことを示すログであり、パネルに画像が見えた証拠ではない。LCD実表示は目視確認する。
- LCDが黒い、または映像が更新されない場合は不合格。UART上でフレームが提示されたログがあっても合格にしない。
- 非致命のカメラ/CSIエラーが出た場合は、件数と表示・推論への影響を記録する。フレームsequenceが進まない、または画面が止まる場合は不合格。
- RAMロード成功は永続書込み成功を意味しない。外部フラッシュへの書込みを行った場合は、別途その方法と検証結果を記録する。
